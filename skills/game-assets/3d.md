# 3D models (.glb) from one image

# Imagine 3D

Everything goes through `<skill dir>/scripts/three_d.py` (Python 3, stdlib only). Run
it as `python3 <skill dir>/scripts/three_d.py ...`; on Windows use `py -3`. Never call
the endpoint with hand-written curl: the script owns credential resolution and
never prints the bearer.

## Credential

The Grok Build session (`grok login`) in `$GROK_AUTH_PATH`, else
`$GROK_HOME/auth.json`, else `~/.cook/auth.json`: the same credential the
built-in `image_gen` tool uses, billed to that session's team. API keys are not
used.

Run `auth` first. It prints the file, email, team, and seconds until expiry,
never the token. Do not `cat`, `jq`, or otherwise read `auth.json` yourself, and
do not paste anything from it into the conversation. If `auth` reports the
session expired, the running Grok client refreshes it on its next request: send
a message in an active `grok` session (or `grok login`) and retry. The script
deliberately does not refresh tokens.

## Access

3D generation is enabled per team. Expected denials:

- `403 permission-denied "Access to the 3d endpoint is denied"` — the team is
  not enabled for 3D generation. Report it and stop; it is not a bug.
- `404 {"code":"not-found", ... does not have access}` — the team cannot use
  the requested model.
- `404 {"error":{"code":404, ...}}` — a transient gateway 404. The script
  retries it up to 3 times; if it persists, report it as a service issue.

Use `models` to confirm the model is available before spending a generation.

## Source image

One image becomes the whole mesh, so it decides the result. Converts well: a
single centered subject, the entire object visible (nothing cropped by the
frame), plain flat background, 3/4 or front view, even lighting. Fails: a
cropped subject, a busy scene, several subjects, a strong cast shadow or
baked-in ground.

If the user has no image, make one first with `image_gen` following the
`imagine` skill (reference-first for real people applies), read it back
against the list above, and only then run `generate` on that file. A subject
that already has a canonical reference image (a recurring game character, a
product shot) is converted from that image, not from a new generation.

## Commands

```bash
python3 <skill dir>/scripts/three_d.py auth
python3 <skill dir>/scripts/three_d.py models                      # list; or: models grok-imagine-3d
python3 <skill dir>/scripts/three_d.py generate --image photo.png --seed 7 --out out/model.glb
python3 <skill dir>/scripts/three_d.py poll <request_id> --out out/model.glb
```

`generate` accepts a local JPEG/PNG/WebP (sent as a data URL), an https URL, or
a data URL; each side must be ≤ 4096 px. Optional: `--model` (default
`grok-imagine-3d`), `--seed`, `--store name.glb` (Files API copy), `--user`,
`--no-wait`. It posts, prints `{"request_id"}` to stderr, polls `GET /v1/3d/{id}`
every `--interval` s (default 5) until `done`/`failed` or `--timeout` (default
660 s), then prints a result summary as JSON. With `--out` it downloads and
validates the `.glb`. Exit 0 only on `done` with a valid download if requested.

## Reading results

- `done`: `asset.url` is a public `.glb`. Expect roughly 10–20 s; meshes are
  not bit-identical across runs even with the same seed.
- `failed`: `error.code` is one of `invalid_argument` (input rejected, incl.
  content policy), `permission_denied`, `failed_precondition`,
  `service_unavailable` (retry later), `internal_error` (timed out). Relay
  `error.message`; do not retry content-policy failures with a reworded request.
- Synchronous `400` before a request id (oversized image, non-`.glb` storage
  filename) means nothing was billed.

On success, link to the downloaded file by its short relative path. If the mesh is then mounted in a y-up, right-handed engine (Three.js and similar), load the `threejs-frame-conventions` skill and measure the asset front — do not hard-code a yaw.
